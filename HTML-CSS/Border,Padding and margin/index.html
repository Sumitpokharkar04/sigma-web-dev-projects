PART 1: Audit & Research

A forensic breakdown of every visual, structural, hierarchy, and interaction failure across all four audited screens. Each issue is categorised, explained, and cross-referenced with premium desktop app patterns.

1.1 Settings Home — 8 Critical Failures

Issue Failure Description
ISSUE 01 · SPACE Cards are 50% empty air Each card is ~170px tall with an icon and 2 lines of text — a 1:3 content-to-whitespace ratio. On a 1280px desktop, operators see only 4 cards before scrolling. Premium desktop apps (Linear, Raycast) target 44px row height for navigation items. The current cards should be compressed to compact 44-52px rows.
ISSUE 02 · HIERARCHY Everything weighs the same Farm Profile, Invoice Config, Appearance, About — all cards are identical in size, weight, and colour. The eye has no entry point. There is no primary, secondary, or tertiary tier. Premium apps use 3 distinct visual layers: hero status > feature settings > utility links.
ISSUE 03 · ICONS Icons are decorative noise in purple circles Icons sit in a purple-tinted circle above the title in an ad-hoc arrangement. They are too small for the container, misaligned with text, and the circle wrapping adds visual complexity without adding meaning. Remove the containers. Inline icons with labels at 16px.
ISSUE 04 · STATUS "Backup Overdue" badge is buried The most urgent status in the entire settings section — a data safety warning — is a small amber tag in the card top-right corner. A business operator focused on another task can easily miss it. It must drive the entire card's visual state (amber border, amber background tint, CTA button inline).
ISSUE 05 · SECTION LABELS Description text under labels is redundant FARM SETTINGS → throwaway description paragraph → cards. The description adds no information the section label and card descriptions don't already communicate. Removing it saves 40px per section and makes the layout feel more like a professional tool.
ISSUE 06 · FOOTER Bottom info bar is timid, invisible, and cut off The grey info bar at the very bottom is below the visible viewport fold, uses a tiny info icon that implies it's a tooltip, and is visually identical to a disabled footer. This is important contextual information (Farm vs App data scope) and deserves a proper inline callout treatment.
ISSUE 07 · NAVIGATION No "you are here" state on detail pages After clicking Farm Profile and landing on the detail page, there is only a back arrow. No breadcrumb, no sub-nav active state, no indication of which settings group the user is in. VS Code, Linear, and Raycast all show persistent sub-navigation with the active item highlighted.
ISSUE 08 · CONTENT WIDTH Cards waste 40% of available desktop width With a 240px sidebar, the content area is ~1040px wide. Each two-column card has ~480px of available space but uses ~80px for icon+text, leaving 400px of empty card body. Desktop apps should use this horizontal space for current-value displays, status indicators, or secondary metadata.

1.2 Invoice Configuration — 5 Failures

Issue Failure Description
ISSUE 01 · LAYOUT Single column wastes 60% of horizontal space The Invoice Numbering card is 880px wide but contains only 2 inputs and 1 toggle. All this horizontal space is wasted. The correct pattern (Stripe, Vercel, Linear) is a two-column layout: controls on the left 55%, live context/preview on the right 45%.
ISSUE 02 · FEEDBACK No live invoice preview exists The operator is configuring how their invoice will look, but receives no visual feedback. The "Next invoice will be: INV-2026-001" pill is the right idea but poorly positioned and too small. A persistent mini-invoice preview panel on the right side would make this page immediately understandable.
ISSUE 03 · NESTING Card-inside-section creates unnecessary visual depth Section heading → description → full-width white card → form inputs. This double-wrapping adds a visual layer without purpose. The correct pattern is: section heading directly above inputs, no intermediate card container. Fields sit on the page background.
ISSUE 04 · GST SELECTOR Radio cards are disconnected from consequences The three GST display options are plain labelled radio buttons. The operator has no way to understand what "Show full GST breakdown" vs "Show GST total only" will look like on their actual invoice without previewing a real invoice. Each option needs a 3-line mini invoice illustration.
ISSUE 05 · SAVE STATE No unsaved changes indicator or save confirmation The Save Changes button in the top-right has no state. After saving, nothing changes on screen. After making changes, nothing indicates that unsaved data exists. VS Code, Linear, Notion, and Figma all show inline unsaved-state indicators and save confirmation feedback.

1.3 Backup & Recovery — 4 Failures

Issue Failure Description
ISSUE 01 · STATUS CARD Overdue warning lacks visual urgency and primary CTA The amber "Backup overdue" card is the correct idea but weakly executed: narrow, left-border only, tiny warning icon. In a business app, backup failure is a critical event. The status card must span the full content width, be impossible to miss, and contain an inline "Back Up Now" button as the primary CTA.
ISSUE 02 · PRIMARY ACTION "Backup Now" is buried mid-page as a secondary card The Backup Now action uses an outlined (secondary) purple button inside a mid-page card. Since creating a backup is the primary action on this page, it should be a filled primary button prominently placed — ideally inside the status banner at the top, not a separate card below.
ISSUE 03 · DANGER ZONE Danger zone is underdesigned and visually quiet The danger zone uses a red card border and red label — structurally correct — but the Reset Settings button is a ghost/outline style that looks secondary. Vercel, GitHub, Railway, and Render all use a full red-tinted background region (#FFF0F0) for the entire danger zone. The destructive button must be visually distinct from every other button on the page.
ISSUE 04 · CONSISTENCY Frequency selector contradicts Invoice Config radio style Daily / Every 3 Days / Weekly uses a pill-style segmented group. Invoice Config uses full-width radio cards. These are the same type of single-choice selection, expressed with two completely different visual patterns on two settings pages within the same module. Pick one pattern and apply it everywhere.

1.4 Benchmark Patterns from Premium Desktop Apps

App Pattern Observed Apply to DSMS
Linear Settings uses a compact left sub-nav list (20-30px rows). Content area uses label-left + control-right on same row. Replace card grid with master-detail panel. Two-column label+control layout on all detail pages.
Stripe Setting rows full-width with label, description, inline action. Status dots (green/amber) next to labels. Inline value badges on every settings row. Green/amber dot on Farm Profile and Backup rows.
Raycast Two-column master-detail: compact icon+label list left, detail right. Right panel updates in place. 36-40px row height. Persistent left settings panel inside content area. No full-page navigation for settings detail views.
Vercel Danger zones: red-tinted background #FFF5F5 for entire section. Destructive buttons red-filled inside zone. Apply directly to Backup danger zone. Full-width red background container, not just a card border.
VS Code Modified settings show a blue dot. Current value visible inline. Settings rows — no card wrappers. Show current values as inline badges on settings home rows. No card containers on detail pages.
Figma Form fields tightly packed at 32px height, 8px gap. 11px caps labels. Helper text 11px muted. No card wrappers. Apply to all DSMS detail pages. Remove card-inside-section pattern.

PART 2: Redesign Strategy

2.1 Core Layout Shift: Card Grid → Master-Detail Panel

→ The single highest-leverage improvement: replace the card grid with a persistent master-detail panel layout. Left panel (240px): compact row list with all section names, icons, and current-value badges. Right panel (flex): renders the active section in place. No full-page navigation. This is how Linear, Raycast, macOS System Settings, VS Code, and Figma all implement settings.
Screen BEFORE (Current) AFTER (Redesign)
Settings Home 2-column card grid. 170px cards. No values visible. Must click in to see current state. 6+ cards before scroll. Left panel: 44px compact rows with icon, label, current-value badge. Right panel: active section renders in place. All current values visible at a glance.
Invoice Config Single full-width column. Card-inside-section nesting. No preview. No save state. Left 55%: flat form fields on page background. Right 45%: sticky live invoice preview. Unsaved changes sticky bar.
Backup Page Amber badge in card corner. Backup Now mid-page outlined button. Simple red border on danger zone. Full-width 3-state status banner with inline CTA. Danger zone: full red-tinted region. Red-filled destructive button.
Appearance Separate sections with card wrappers per setting group. No live preview. Setting-row pattern: label left + control inline right. 80px live preview strip updates in real-time.

2.2 Settings Home — Left Panel Row Anatomy

Each row in the left settings panel: height 44px, padding 0 16px, flex row, align-items center. Left: Lucide icon 16px text-tertiary + 8px gap + label 14px/500 text-primary. Right: conditional value badge + chevron-right 14px text-tertiary. Hover state: background purple-50. Active state: background purple-50 + border-left 3px purple-600 + label color purple-700. Value badges: Farm Profile = green dot (complete) or amber dot (missing fields). Invoice Config = monospace pill "INV-2026-". Backup = "12d ago" in amber or "Today" in green.

3.4 Elevation: Borders vs. Shadows

Layer Visual Treatment When To Use
Base / flat No border, no shadow. Background: page bg (#F8F9FA). Section headings, form fields sitting directly on the page (Figma/Linear pattern).
Raised / card 1px border #E5E7EB. No shadow. Background: white. Setting cards, invoice preview panel, master-detail left panel.
Floating / modal 1px border + box-shadow: 0 4px 16px rgba(0,0,0,0.08). Confirmation dialogs (Restore Backup confirm), the unsaved changes sticky bar.
Status banner Left border 4px solid (semantic color). Background: semantic-50. Backup status banner, overdue warning, success callouts.
Danger zone 1px border #FCA5A5. Background: #FFF5F5. No shadow. Reset Settings section. Color communicates danger; no shadow needed.
✓ Golden Rule: Use borders to contain, shadows to lift. In a desktop settings UI, almost nothing should float. Shadows are reserved for genuinely floating elements: modals, dropdowns, the sticky unsaved-changes bar.

PART 4: Technology & Component Stack

4.1 UI / Headless Library Evaluation

Library Verdict Rationale & Usage
Radix UI Primitives USE Headless, unstyled primitives for Dialog, DropdownMenu, Select, Switch, RadioGroup. Zero conflict with MUI. Use for the master-detail panel, backup confirmation dialog, and GST radio group where MUI's opinionated styling conflicts with the redesign.
React Hook Form USE Critical for Farm Profile and Invoice Config. Gives dirty state detection (powers unsaved changes bar), field-level validation, and optimistic save patterns. Current MUI+useState approach is the reason unsaved-state feedback is missing.
shadcn/ui ADAPT Cannot use the Tailwind layer in MUI context, but individual component source files (RadioGroup, SegmentedControl) can be copied and adapted for the GST selector and frequency picker.
Mantine SKIP Excellent library but introduces a competing design system. Reconciling Mantine spacing/color/radius tokens with MUI theme takes weeks. Never mix two full design systems in the same app.
MUI X / Pro FUTURE DateTimePicker useful for backup time selector. DataGrid Pro valuable for future table-heavy pages. Not required for the Settings module specifically.
Ark UI SKIP State-machine based headless components. Powerful but heavy for a settings module. Radix covers the same primitives with a simpler API.

4.2 Animation Library Evaluation

Library Verdict Specific Use in DSMS Settings
Framer Motion USE — selectively Use for: (1) unsaved-changes sticky bar sliding up from bottom, (2) status banner transitioning between states (green to amber), (3) master-detail right panel cross-fading on section switch. Do NOT animate everything — desktop apps feel premium through restraint.
AutoAnimate USE One-line addition: useAutoAnimate(ref). Perfect for auto-backup sub-fields appearing/disappearing when the toggle is switched. Zero configuration, production-safe, negligible Electron bundle cost.
Motion One SKIP Web Animations API wrapper. Better for vanilla JS contexts. Framer Motion's declarative API is far better suited to React's component model for the interactions described above.
! Note: Animation budget for settings pages: maximum 3 animated interactions total. Unsaved changes bar, status banner state change, panel section transition. Everything else: instant or CSS transition 150ms ease only.

4.3 Icon Set Recommendation

Icon Set Verdict Rationale
MUI Icons (current) REPLACE The root cause of the icon quality problem. MUI Material Icons are designed for Android mobile touch targets at 48px. At desktop density (16-18px), they appear too heavy-stroked and "rounded consumer." They read as an Android app, not a professional desktop business tool.
Lucide React PRIMARY 1400+ icons. Thin 1.5px stroke. Consistent optical sizing. Tree-shakeable. Used by Linear, Vercel, Notion, and GitHub. Direct replacement: import { Store, FileText, Palette, Database } from "lucide-react". Target sizes: 16px inline, 18px for row icons, 20px max decorative.
Phosphor Icons ALTERNATIVE 6 weights per icon (thin to fill). Slightly more expressive than Lucide. Consider if you need filled variants for active nav states. Do not mix with Lucide — using both creates visual inconsistency.
